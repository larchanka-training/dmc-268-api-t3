# Backend Project Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current bare pip/single-file FastAPI skeleton with a uv-managed project skeleton on the approved stack (FastAPI, SQLAlchemy, PostgreSQL, Ollama SDK, uv, Ruff, Pylint), runnable via Docker Compose, exposing only `GET /healthcheck`.

**Architecture:** A small `app/` package: `config.py` reads Postgres/Ollama settings from env vars with no third-party settings library; `database.py` builds a lazy (non-connecting-at-import) SQLAlchemy engine from that config; `ollama_client.py` builds an `ollama.Client` the same way; `api/healthcheck.py` is the only route, mounted in `main.py`. Docker Compose runs the API (built via a `uv`-based Dockerfile) plus a Postgres service with a named volume; Ollama stays external via `OLLAMA_HOST`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.x, PostgreSQL via `psycopg` v3 (binary), `ollama` SDK, uv, Ruff, Pylint. Dev-only: `pytest` + `httpx` (required transitively by FastAPI's `TestClient`) — approved with the user as the one addition beyond the spec's tool list, scoped strictly to testing.

**Spec:** Agent Specification: Backend Project Skeleton and Tooling (provided in conversation, not a repo file).

## Global Constraints

- Approved stack only: Python, FastAPI, SQLAlchemy, PostgreSQL, Ollama SDK, uv, Ruff, Pylint. No Poetry/PDM, no Black/MyPy, no Redis, no other ORM/AI SDK.
- Dev-only exception (user-approved): `pytest` + `httpx` for the healthcheck test — not used in the app runtime, not added to Docker's runtime image beyond what `uv sync --no-dev` already excludes.
- Python version: 3.12 everywhere (`pyproject.toml` `requires-python`, Dockerfile base image).
- Postgres driver: `psycopg[binary]` (v3), sync SQLAlchemy engine — no async engine, no `asyncpg`.
- Only endpoint: `GET /healthcheck` → `200 {"status": "ok"}`. No other business endpoints, auth, migrations, or AI endpoints.
- App must be importable/startable with zero DB or Ollama connectivity — `create_engine(...)` and `ollama.Client(...)` must not connect eagerly.
- Compose has exactly two services: `api`, `postgres`. Ollama is external only, via `OLLAMA_HOST`.
- `uv.lock` must be committed and reflect the real dependency set (generated by running `uv` commands, not hand-written).

```python
import os
from dataclasses import dataclass


@dataclass(frozen=True)
class Settings:
    postgres_db: str
    postgres_user: str
    postgres_password: str
    postgres_host: str
    postgres_port: int
    ollama_host: str

    @property
    def database_url(self) -> str:
        return (
            f"postgresql+psycopg://{self.postgres_user}:{self.postgres_password}"
            f"@{self.postgres_host}:{self.postgres_port}/{self.postgres_db}"
        )


def load_settings() -> Settings:
    return Settings(
        postgres_db=os.getenv("POSTGRES_DB", "app"),
        postgres_user=os.getenv("POSTGRES_USER", "app"),
        postgres_password=os.getenv("POSTGRES_PASSWORD", "app"),
        postgres_host=os.getenv("POSTGRES_HOST", "postgres"),
        postgres_port=int(os.getenv("POSTGRES_PORT", "5432")),
        ollama_host=os.getenv("OLLAMA_HOST", "http://host.docker.internal:11434"),
    )


settings = load_settings()
```

- [ ] **Step 2: Write `Dockerfile`**

```dockerfile
FROM python:3.12-slim

COPY --from=ghcr.io/astral-sh/uv:0.12 /uv /uvx /usr/local/bin/

WORKDIR /app

ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy \
    PATH="/app/.venv/bin:$PATH"

COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project

# No [build-system] is configured, so this is a virtual project (see
# uv.lock: source = { virtual = "." }) — `app` is never installed into the
# venv. uvicorn's own CLI inserts --app-dir (defaulting to ".") into
# sys.path, which is how `app.main` resolves at runtime below.
COPY app ./app

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

> **Corrected during final review:** the original snippet used `CMD ["uv",
> "run", "uvicorn", ...]`, which performs an implicit `uv sync` at every
> container start — including the `dev` dependency group, since `uv run`
> enables it by default. This both re-introduces pytest/pylint/ruff into
> the running container (violating the Global Constraint that dev deps
> stay out of the runtime image) and makes startup depend on PyPI
> reachability. The corrected CMD invokes `uvicorn` directly via `PATH`,
> which was already built with `--no-dev` and never touched again. Also
> pinned the `uv` base image tag (was `:latest`) so a future uv release
> can't silently change build/run semantics.

- [ ] **Step 3: Write `docker-compose.yml`**
