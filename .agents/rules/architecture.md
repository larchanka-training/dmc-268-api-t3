# Инварианты Review Orchestrator

Эти требования задают поведение будущей реализации; имена таблиц, endpoints и event DTO здесь не утверждаются.

## Запуски и идемпотентность

Каждый логический запуск имеет собственный `run_id` и фиксирует tenant/repository, PR number, base/head/merge-base SHA, инициатора и версии rules/prompt/model. Все файлы берутся из этого снимка. Обновление PR не изменяет прошлый отчёт.

| Событие | Требуемый результат |
| --- | --- |
| Первая доставка подписанного события | Один новый запуск |
| Повтор того же события, в том числе одновременно | Тот же запуск, без повторного результата |
| Новое событие нового коммита | Новый снимок и запуск согласно политике |
| Явный пользовательский rerun на том же SHA | Новый `run_id`, прежний отчёт сохраняется |
| Транспортный retry того же запроса rerun | Тот же запуск этой пользовательской операции |

Не используй только SHA/PR как глобальный ключ дедупликации: это блокирует явный rerun. Для автоматической доставки нужен стабильный идентификатор исходного события в области tenant/provider/integration; его надо сохранять при повторном помещении в очередь. Для ручного действия — отдельный ключ операции, переиспользуемый при сетевом retry; следующее явное действие получает новый ключ.

Конкурентную дедупликацию обеспечивает атомарная операция и уникальное ограничение долговечного хранилища. `SELECT → INSERT` без ограничения, process-local set и TTL-кэш не достаточны. При конфликте возвращается уже созданный запуск; при несовместимом payload с тем же ключом — явная ошибка. Значения ключей не дают доступа к чужим данным.

## Доставка и жизненный цикл

RabbitMQ допускает повторную доставку. Ack только после долговечного принятия работы/сохранения результата; повтор после сбоя безопасен на каждой границе. DB transaction и publish в брокер не атомарны сами по себе: предусмотреть outbox либо другую проверяемую схему восстановления, согласовав её с техлидом. Retries ограничены, с backoff/jitter; исчерпание попыток даёт наблюдаемую ошибку/DLQ по принятой конфигурации. Poison event не ходит по бесконечному requeue.

Переходы состояний валидируются; конкурирующий worker не перезаписывает завершённый run. Отдельно различаются успешное полное ревью, частичный результат, ошибка и отмена; пустой массив findings при сбое не означает «дефектов нет». Согласовать названия статусов с API, не выводить их из этого текста автоматически.

## VcsProvider

Граница провайдера включает `getPullRequest`, `getDiff`, `getFile`, `getCommit`, `getRepository`, `publishComment`. Представленная в задании TypeScript-сигнатура описывает порт; backend реализует эквивалент в Python, а не Node.js-сервис без отдельного решения.

Аргументы и DTO уточняются при реализации. Чтение файла привязано к конкретному SHA; diff — к согласованным base/head/merge-base. Учесть pagination, rename/delete, binary/truncated files, 403/404, 429/Retry-After, timeout, отмену и лимит объёма. Frontend не обращается к VCS с секретом интеграции.

`publishComment` — отдельный побочный эффект, включаемый политикой. Перед публикацией сверить актуальность SHA и права; хранить ключ публикации и provider comment ID, чтобы не дублировать комментарий при retry. Возврат `Promise<void>` сам по себе не обеспечивает идемпотентность. Генерация отчёта не зависит от успеха необязательной публикации.

## Доступ, лимиты и сеть

JWT проверяется по подписи, разрешённым алгоритмам, сроку и принятой issuer/audience policy. Валидный JWT не заменяет проверку доступа к repository/run/report при запуске, чтении и скачивании. Проверять межтенантные запросы и отзыв прав. Входящие webhooks проходят проверку подлинности до постановки в очередь.

Rate limit ограничивает запросы пользователя/tenant и вызовы VCS/модели. Retry учитывает общий бюджет времени и запросов, а не начинает его заново. Конкретный distributed limiter и Redis — открытые решения; локальный счётчик не выдаётся за общий лимит нескольких workers.

Sub-network означает контролируемые границы доступа: DB, broker и Ollama не публикуются наружу случайно. Нужные направления API→DB/broker, worker→VCS/Ollama фиксируются в deployment-конфигурации; этот пакет не вводит CIDR/порты/новые сервисы. URL из PR не дают права на произвольный fetch во внутреннюю сеть.
