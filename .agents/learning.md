# Практикум команды: от задачи к проверенному изменению

На каждую часть отведите 10–15 минут. Сначала сформулируйте ответ сами, затем используйте скилл и сравните. Цель — уметь объяснить решение на ревью.

1. Откройте `main.py` и `pyproject.toml`. Найдите работающий health endpoint. В [README](README.md) проверьте отличие main от PR #1. Зачем: AI часто пишет правдоподобный код для ещё не существующей структуры.
2. Прочитайте [архитектуру](rules/architecture.md). Нарисуйте три доставки события E и два нажатия rerun на одном SHA. Подпишите `run_id` и ключи операций. Зачем: повтор сети не равен новому намерению пользователя.
3. Заполните [шаблон реализации](templates/implement.md) для проверки доступа к отчёту. Укажите субъект, ресурс, успешный ответ и отказ. Зачем: «есть JWT» ещё не означает «можно читать этот run».
4. Прочитайте [сигнатуры](prompts/signatures.md), [учебный diff](validation/fixtures/review.diff) и [пример результата](validation/fixtures/valid.json). Объясните вход, на котором возникает ошибка, и исправление. Затем проверьте результат по [инструкции](validation/README.md).
5. Измените `head_sha` в копии примера и запустите валидатор. Он обязан отказать. Зачем: правильный JSON может относиться к другому коммиту.
6. По [плану тестов](templates/test-plan.md) объясните, какие проверки требуют настоящего PostgreSQL/RabbitMQ, а какие можно выполнить без инфраструктуры.

## Самопроверка

| Вопрос | Объяснение |
| --- | --- |
| Почему уникальность только по SHA неверна? | Два явных rerun на одном SHA должны дать разные run_id. |
| Почему SELECT перед INSERT не спасает от дубля? | Два worker могут одновременно не найти запись; нужен атомарный конфликт на уровне БД. |
| Почему ack до сохранения опасен? | При падении worker сообщение уже удалено, а результата нет. |
| Почему пустой findings не всегда хороший результат? | Модель могла не получить весь diff или завершиться ошибкой. Смотрите coverage. |
| Почему найденная сигнатура ещё не дефект? | Нужны достижимый сценарий, нарушение контракта и проверка защит в окружающем коде. |
| Что доказывает валидатор? | Формат и связь с доверенным контекстом, но не истинность рассуждений модели. |

На командном ревью покажите один конкретный сценарий: вход → поведение до → поведение после → проверка. Не пересказывайте весь скилл.
